# Карта проекта

Короткая техническая справка для веб-прототипа мобильной игры про управление подпольным баром. Актуальные игровые правила находятся в `gdd.md`.

Прототип реализует многоэтажное строительство бара, управление меню, расчет одновременных лимитов клиентов и симуляцию обслуживания с плавным перемещением.

## Стек

- TypeScript в строгом режиме.
- Vite.
- Vanilla DOM без UI-фреймворка.
- Веб-прототип с мобильным игровым экраном в портретном формате 9:20.
- Персонажи, мебель и предметные слои ячеек развиваются как SVG; PNG используется для фонов, общих текстур и отдельных растровых иллюстраций. Все предметные слои ячеек, напитки, пять типов клиентов, бармены, официанты и бетонные поверхности используют SVG. Иконки интерфейса используют SVG и PNG.
- `node:test` и `tsx` для тестов игровой логики.

## Основные команды

```powershell
npm.cmd run dev
npm.cmd run typecheck
npm.cmd test
npm.cmd run build
npm.cmd run preview
start-prototype.bat
```

`start-prototype.bat` при необходимости устанавливает зависимости, запускает Vite на `http://127.0.0.1:5173/` и открывает прототип в браузере.

## Публикация на GitHub Pages

`.github/workflows/pages.yml` устанавливает зависимости через `npm ci`, выполняет тесты, собирает прототип и публикует только `dist/`. Git LFS загружает настоящие изображения и шрифты при checkout. Базовый путь сборки определяется из настроек Pages: поддерживаются адрес репозитория, сайт в корне домена и собственный домен. Настройка `base: "./"` в Vite сохраняется для обычной локальной сборки.

1. Загрузите проект в репозиторий GitHub вместе с Git LFS-объектами. Workflow ожидает основную ветку `main`; если она называется иначе, измените `on.push.branches` в workflow.
2. В репозитории откройте **Settings → Pages → Build and deployment → Source** и выберите **GitHub Actions**.
3. Отправьте изменения в `main` или запустите **Actions → Deploy to GitHub Pages → Run workflow**. Адрес опубликованного прототипа появится в окружении `github-pages` и настройках Pages.

Для локальной проверки адреса с префиксом репозитория выполните `npm.cmd run build -- --base=/имя-репозитория/`, затем `npm.cmd run preview` и откройте этот путь на адресе сервера предпросмотра. Обычная локальная сборка: `npm.cmd run build`.

Workflow следует [официальной схеме публикации Vite на GitHub Pages](https://vite.dev/guide/static-deploy.html#github-pages). Секреты и отдельная ветка с результатом сборки не требуются.

## Графические файлы и Git LFS

Растровые изображения (PNG, JPG, JPEG, GIF, WebP, ICO) и шрифты (TTF, OTF, WOFF, WOFF2) отслеживаются через Git LFS по правилам .gitattributes. SVG, исходный код и лицензии хранятся обычным Git. Перед работой с репозиторием установите Git LFS и выполните git lfs install; для загрузки ассетов в существующую копию используйте git lfs pull.

## Структура

### Игровой слой

- `src/types.ts` — типы состояния, ячеек, напитков и персонажей.
- `src/balance.json` — балансовые параметры, напитки, типы клиентов и цепочка заданий.
- `src/config.ts` — технические параметры и типизированный доступ к игровому балансу.
- `src/geometry.ts` — общая пиксельная геометрия карты и длительность перемещения персонажей.
- `src/game.ts` — публичный barrel игрового слоя.
- `src/game/state.ts` — создание, сохранение и загрузка состояния.
- `src/game/selectors.ts` — вместимость, бонусы ячеек и чтение сущностей.
- `src/game/economy.ts` — уровни, шансы, скорость прихода и цены напитков и клиентов.
- `src/game/progression.ts` — строительство, улучшения, разблокировки и выбор заказов.
- `src/game/decor.ts` — общие разблокировки декора по типу ячейки, индивидуальный выбор и подтверждение уведомлений.
- `src/game/tiers.ts` — границы тиров ячеек, требуемые исследования и прогресс уровня внутри тира.
- `src/game/infrastructure.ts` — пределы ширины и глубины карты по исследованиям.
- `src/game/navigation.ts` — поиск маршрутов по этажам и лестницам.
- `src/game/personnel.ts` — синхронизация барменов и официантов, предоставляемых кранами и стойками официанта.
- `src/game/simulation.ts` — интервальный приход клиентов, очереди, перемещение и обслуживание.
- `src/game/hold.ts` — запас ускорения, перегрев, кулдаун и таймеры механики холда.
- `src/game/quests.ts` — прогресс цепочки заданий, накопительные события, сбор наград и разблокировки.
- `src/game/research.ts` — определения апгрейдов, запуск, таймер и выдача результатов.
- `src/game/offers.ts` — доступность подарков, взвешенный розыгрыш, раскладка слотов, выдача наград и кулдаун.

### Интерфейс

- `src/main.ts` — состояние приложения, делегированные действия и игровой цикл.
- `src/ui/app.ts` — оболочка, постоянные панели и служебные controls.
- `src/ui/dom.ts` — обновление DOM по снимкам разметки с сохранением неизменившихся узлов и SVG-изображений.
- `src/ui/animation.ts` — покадровое обновление непрерывных индикаторов интерфейса и анимации подарка.
- `src/ui/attention.ts` — правила отображения индикаторов внимания для заданий и разблокировок.
- `src/ui/map.ts` — карта и персонажи.
- `src/ui/map-camera.ts` — границы и кеш геометрии камеры; ограничение движения в состоянии и покадровое применение положения сцены.
- `src/ui/map-fixtures.ts` — предметные SVG ячеек, слои мебели и соединение стоек со стульями, кранов и стоек официанта.
- `src/ui/map-assets.ts` — каталог путей общих поверхностей, текстуры кирпича и предметных SVG всех ячеек; части всех клиентов, бармена и официанта, их точки крепления из конфига и порядок отрисовки.
- `public/art/drinks/` — фронтальные SVG всех напитков для карты: кружки бормотухи, лагера и портера с ручкой справа, стаканы эля и Гиннеса; отображаются у клиента, бармена и официанта по напитку заказа.
- `public/art/characters/<sailors|clerks|irish|cops|mafia>/<side|back>/` — используемые SVG-части клиентов: голова, тело и две ладони; общий масштаб и точки сборки заданы в `CONFIG.mapArt.customer`.
- `public/art/characters/bartender/<front|side>/` — используемые SVG-части бармена: голова, тело и две ладони; точки сборки заданы в `CONFIG.mapArt.bartender`.
- `public/art/characters/waiter/<side|back>/` — используемые SVG-части официанта: голова, тело и две ладони; точки сборки заданы в `CONFIG.mapArt.waiter`.
- SVG мебели стойки и частей матроса используют встроенные размеры в пикселях сцены, `viewBox` от `0 0` и якорь по центру нижнего края (`data-anchor="bottom-center"`). Точки сборки клиентов заданы в `CONFIG.mapArt.customer`. Исходная геометрия сохранена в группе `artwork` с преобразованием в координаты холста.
- `src/ui/map-art.ts` — покрытие области камеры фоном земли и городской поверхностью, привязанной к входу.
- `public/art/environment/` — используемые растровые фоны земли и городской поверхности.
- `public/art/cells/<type>/tier-1/` — используемые предметные ассеты ячеек: SVG центра стойки, левого и правого краёв в вариантах завершения и продолжения, повторяемого табурета; SVG бочки и центра стойки крана, использующего общие со стойкой края; SVG закрытой двери входа и лестницы зигзагом с перилами; узкой стойки официанта с отдельным клошем, столика и повторяемых стульев со спинками, открытой туалетной кабинки, раковины, сушилки, мишени дартса и бильярдного стола. Стулья показаны сбоку и зеркально разворачиваются к столику. Спинки и сиденья стульев, задние и передние части сантехники разделены по слоям перекрытия. Фронтальный бильярдный стол с крупными шарами — единый SVG, настенная стойка с тремя вертикальными киями — отдельный SVG.
- `public/art/cells/<type>/decor/<cabaret|techno|japan>/` — предметные SVG-варианты мебели девяти улучшаемых типов; классика использует прежние пути `tier-1`.
- Края `styled-<left|right>-<end|continuation>.svg` общие для декора стойки со стульями, крана и стойки официанта; классика использует прежние края из `tier-1`.
- Предметные SVG `countertop-prop.svg` на стойке со стульями: свечи кабаре, чайник стимпанка, фонарик Японии. Внутренний ID и каталог `techno` соответствуют стилю «Стимпанк».
- `public/art/cells/<type>/decor/<style>/accent.svg` — отдельные украшения остальных восьми улучшаемых типов: букеты, чайники, зеркала, манометры, таблички и светильники. Пути задаёт `CELL_DECOR_ACCENTS`, размеры, позиции и слои — `CONFIG.mapArt.decorAccents`.
- `public/art/icons/decor/` — четыре общие SVG-иконки стилей.
- `public/art/shared/textures/brick.png` — единая растровая текстура кирпича всех ячеек; параметры повторения — `CONFIG.mapArt.brickWall`.
- `public/art/shared/surfaces/` — общие SVG бетонного пола и потолка, растягиваемые по ширине ячейки, и наружной стены по краям построенного этажа.
- `src/ui/panels.ts` — экраны меню, клиентов, строительства и фокуса.
- `src/ui/types.ts` — временное состояние интерфейса.
- `src/ui/icons.ts` — общий каталог графических иконок, рендер и сопоставления исследований и разблокировок.
- `public/art/icons/` — 24 PNG-иконки (23 круглые и значок рекламы), 19 SVG-пиктограмм.
- `src/ui/format.ts` — форматирование цены заказа для отображения.
- `src/ui/quests.ts` — цепочка контрольных точек и карточка активного задания.
- `src/ui/research.ts` — экран апгрейдов и состояния его карточек.
- `src/ui/offers.ts` — иконка подарка, модальное окно, вращение слотов и показ результата.
- `src/ui/decor.ts` — панель декора, открытие и закрытие, однократная прокрутка к новому варианту.
- `src/ui/energy.ts` — окно энергии, прогресс восстановления, таймер и кнопка пополнения.
- `src/styles/*.css` — тематические стили оболочки, карты и панелей.
- `src/styles/theme.css` — общая мрачная барная тема интерфейса.
- `src/styles/fonts.css`, `src/assets/fonts/` — локальные Oswald и Roboto Condensed с кириллицей и лицензиями OFL.

## Архитектурные границы

1. `loadGame()` восстанавливает совместимое состояние или создает новую игру.
2. UI читает `GameState` и передает действия функциям игрового слоя.
3. `advanceGame()` обновляет детерминированную симуляцию. `main.ts` синхронизирует изменившиеся части DOM; движение, фазы персонажей и непрерывные индикаторы обновляются через `requestAnimationFrame`. Перемещение и масштабирование камеры меняют преобразование существующей сцены.
4. Состояние сохраняется после действий и раз в секунду игрового цикла.
5. Несовместимое сохранение сбрасывается без миграции.

## Правила изменений

- Новые балансовые значения и задания добавлять в `src/balance.json`; технические параметры отображения — в `src/config.ts`.
- Игровые правила реализовывать чистыми функциями в слое игровой логики.
- Рендер каждого экрана держать в соответствующем UI-модуле.
- Общие элементы интерфейса и игровые правила не дублировать.
- Не добавлять историю решений в GDD: документ описывает только актуальное поведение.
- При изменении механики обновлять GDD и тесты; при изменении поведения интерфейса обновлять GDD.
- Визуальные параметры хранить в коде без отдельной текстовой спецификации и UI-контрактных тестов.
- Поддерживать в этом файле актуальную карту модулей и команд.
